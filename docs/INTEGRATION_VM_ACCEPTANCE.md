# Manual acceptance — existing CanvasDeadlineAgent-Smoke only

This checklist is documentation, not permission to control the VM. This coding session does not operate desktop/VM or use real accounts. Earlier UI appearance approval is retained; this new integration candidate still needs native functional acceptance.

1. Keep current VM/environment and protections. Copy the entire new portable folder to a new writable guest directory; keep `_internal`, manifests and old candidates. Do not reinstall Windows, clone or reset snapshots for ordinary updates.
2. Verify ISO and payload SHA-256 from delivered manifests. Run `Check-Runtime.cmd` manually. It must not download/install anything.
3. Keep offline. Run `Launch-Mapping-Probe.cmd`; text must become READY. Inspect that run's `startup-status.json`: mode=mapping_probe, all seven stages, status=ready. Close probe.
4. Run `Launch-QA.cmd` (also default double-click mode). It uses the complete Python backend with explicitly synthetic external-service behavior and a separately marked QA directory. Confirm real frontend, both themes, languages, dashboard, search/course/status/sort, no-due-date placement, descriptions/drawer, local completion/ignore/restore and distinct local/remote histories.
5. Restart QA, check saved local state/settings. QA must reject real credentials, paid calls, scheduler registration, native clipboard/dialogs and actual notifications with an explicit error/status rather than pretend success. The offline HTML preview is a separately labelled Browser Mock Adapter.
6. Native clipboard/file-dialog/scheduler/account tests need later explicit user authorization. `Launch-Live-Integration.cmd` is provided for that later phase; it opens an initially empty separate `%LOCALAPPDATA%\CanvasDeadlineAgent-v1.2-Integration` profile, never seeds demo tasks, does not read v1.1 data, and does not enable monitoring automatically. Do not use it with a marked synthetic QA folder. This session has not run it.
7. After specific authorization, enter personal credentials only in the guest app. Bind Canvas, test identity, click Sync; check cache, coverage and 401/403/429/timeout states. A failed or limited sync must not become 'no assignments'. Verify assignment/quiz dedup and official links. No submission POST is available.
8. Explicitly test each local choice, restart/resync, switch accounts and restore; original Canvas status stays separate. Verify Guardian/weekly/core notification filtering and retained deduplication before enabling any real notification.
9. Explicit PushPlus test: bind token, confirm test dialog. Local configured/API accepted/actual user receipt are three distinct states. Record real delivery only using the matching 'I received' button. Do not send tests automatically. Saved tokens must remain absent from prefilled inputs, state DTO and logs.
10. Scheduler test only after specific authorization: enable monitoring, query status; validate own stable data-directory-derived task identity, least privilege, independent `--scheduled`/`--guardian` execution with GUI closed, timings and cleanup after disabling. Do not touch v1.1 tasks. For custom review profile cleanup, use this candidate with `--remove-task --data-dir <exact review directory>` after user choice. No installer is shipped in this phase.
11. AI is optional/off initially. Without a key, core sync/local actions/reminders still work. Optional test/request requires explicit confirmation. Check invalid_response reason display and unchanged official deadlines. File reads require exact grants; export/cloud previews must match, no automatic upload/submission.
12. Logs: `<chosen data dir>\diagnostics\<run-id>\startup.jsonl`, `startup-status.json`, `resources.json`; bounded backend execution records are in the same SQLite store and visible in the app. Require mode=application, native successful navigation, DOM/bridge/backend/UI Ready plus actual visible content. Never infer native startup or functional success from a headless test alone.

No public/Beta release is approved by this checklist. Complete proxy_tools/WebView2 SDK licence materials, security validation, code signing/distribution policy and real native acceptance remain separate gates. Preserve original evidence and do not disable Defender or add exclusions.
