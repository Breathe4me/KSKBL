# v1.2 WebView bridge

Only `invoke(method, params)` is public. Private paths, SQLite handles, Python objects, native APIs, arbitrary file reads, command execution and credential reads are not capabilities. The app uses bundled local HTML with the ordered WebView2 mapping lifecycle. Untrusted Canvas/provider text is rendered with escaping/textContent, never evaluated.

Every request: method must be an exact allowlisted string; params a JSON object containing exactly documented required/optional keys; serialized request <=20,000 characters. Task keys match `course:(assignment|quiz):id`, must exist in the current cache and match the opaque `account_scope`. Setting keys are validated against DEFAULTS, URLs HTTPS, enums/booleans/ranges validated. Text fields are bounded and cannot contain NUL. Credentials <=4096 characters, notes <=500, ordinary text <=500. All result strings recursively scrub known saved secrets and generic token/URL patterns.

Envelope: `{ok:true,data:...}` or `{ok:false,error:stable_code}`. Arbitrary exception strings and HTTP bodies never cross the bridge. Common codes: `invalid_request`, `operation_failed`, `busy`, `window_closed`, `canvas_configuration_required`, `stale_account`, `official_page_required`, `explicit_native_action_unavailable`, `explicit_ai_confirmation_required`, plus bounded service error codes. `busy` rejects duplicate work instead of queuing another sync. UI shows loading, success/status or error. A window-close flag prevents later UI calls and revokes file access. Service calls run in pywebview worker threads; CLI monitor does not import/create WebView windows.

Notation: **T** = required `key,account_scope`; **C** = required boolean `confirmed:true`. Unknown extra keys fail. No method reads saved credential plaintext into JS.

Workspace operations: `select_files`, `select_folder` require C and native chooser; `revoke` clears grants; `workspace_prompt` requires selected grant; `preview_export` returns exact manifest + ticket; `export` requires C and current single-use ticket; `preview_cloud` returns full text + ticket; `send_cloud` requires C, AI configuration and current single-use preview ticket; `download_materials` requires C and existing assignment attachments, with a separate explicit allowlist for external redirect hosts. No local file is executed, no automatic assessment submission is implemented. Provider/credential/account/context changes invalidate previews.

PushPlus states are deliberately separate: `configured` only means a local saved credential exists; API `accepted` means the provider accepted a request; `delivery_confirmed` is false until the matching receipt is explicitly confirmed by the user. HTTP ambiguity is not success and is not blindly replayed. Explicit retryable failures retain max 3 attempts spaced >=15min. Status DTOs include count, blocking, attempts and earliest retry time, never token or provider body.

Real versus QA: production `Bridge(qa=False)` uses actual services. Explicit QA bypasses external requests, rejects credential/native/paid operations and defaults to a no-DPAPI adapter. Browser Mock Adapter exists only in exported offline HTML and is visibly marked. The integration QA executable defaults to synthetic mode; its `--live --data-dir <separate directory>` entry is for later explicitly authorized manual tests. Scheduled/guardian CLI routes run without a GUI and use exactly the task's data directory. A marked QA directory cannot be opened in real mode.

Credential policy audit (2026-10-22): QA `save_credential` and `remove_credential` return `qa_credentials_disabled`, not the ambiguous historical `credential_entry_unavailable`. `get_state.credential_policy` contains `mode`, `can_save`, and `ai_legacy_rebind_required`; only presence/missing/unreadable status is returned. Live empty input returns `credential_value_required`; DPAPI/write failure returns `credential_storage_failed`. No native credential-reading API is exposed to JavaScript. Entered values are cleared after the explicit save click; previously saved values are never filled into an input.

Live AI secrets are DPAPI ciphertext scoped by the selected provider AND normalized full HTTPS endpoint. AI consumers use the validated configuration snapshot for that particular request. Built-in OpenAI/DeepSeek providers reject a mismatched official endpoint (`ai_endpoint_mismatch` / AI result `provider_endpoint_mismatch`); custom compatible services require selecting Custom. Saving the AI key first saves the currently selected non-secret AI configuration. A legacy unscoped `ai.dpapi` is preserved but cannot safely be attributed to a provider, so requires explicit re-entry; it is not automatically migrated, deleted, or sent. Deletion removes only the current provider/endpoint key. Corrupt optional keys do not break unrelated core credential redaction. Automated DPAPI checks use fabricated keys in fresh temporary directories, not real user profiles.

`--credential-check --data-dir <new empty directory>` is a non-window frozen selfcheck, not live GUI or API acceptance. It exercises the real production Bridge and Windows DPAPI with fabricated strings, refuses an existing nonempty directory, and never creates external clients. Its synthetic production-services folder is marked QA-only to prevent opening it as a live account profile.

P0 assignment mutation ordering: the frontend serializes its RPC transport, awaits drawer file-access revocation before state refresh, and prevents duplicate confirmation while an action is pending. Python's nonblocking Bridge lock, cross-process profile lock and SQLite transactions remain enforced. Busy responses include safe `operation`, `reason` and `blocking_operation`; reasons distinguish `bridge_operation_in_progress`, `profile_operation_in_progress`, and `database_locked`. Diagnostics record fixed operation/state enums, never notes, task content or credentials.

The frontend request deadline restores action buttons but does not cancel Python, release its transport queue slot or automatically retry. Expired queued requests are rejected before dispatch. An active timed-out task write retains its pending task key until the actual reply arrives; an immediate repeat reports `busy` / `outcome_pending`. The user must refresh or restart to verify an uncertain result. Exact repeated state/reason/note/fingerprint does not append another local history entry or increment the tracking revision. A saved state is never substituted for the remote Canvas submission status.
